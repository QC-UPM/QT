# Reproducing the TQT ablation

## Evidence available in this snapshot

The main notebook contains implementation code and saved output from the supplied completed run `run_0f4dee9df4ca`, whose execution log is dated 2026-09-07. The saved summary matches the companion manuscript. Updating this repository's documentation did not rerun the study.

The repository includes a machine-readable extraction of the printed summary. It does not include the original Parquet tensors, a verified subject/session map, or the original external reports, manifests, per-record predictions, braid inventory and checkpoints. File paths printed in the notebook refer to the original author's machine; they are not downloadable artifacts. ## Environment and working directory

Follow the installation commands in the root README. The root `requirements.txt` mirrors `PINNED_REQUIREMENTS` in the notebook. These pins define the managed recovery stack, not a claim that every successful execution used those exact versions: automatic mode can reuse another environment that passes its probe, and the runner records the actual package versions.

Open `ablation_TQC.ipynb` with the kernel working directory set to the repository root. The first code cell is self-contained and invokes `run(CONFIG)` at the end. Edit settings in that cell before executing it. The empty trailing cell can be used to inspect `RESULTS` after completion. The new introductory Markdown cell does not execute code.

| Setting | Repository default | Use |
| :--- | :--- | :--- |
| `data_dir` | `data/outs` | Directory containing input Parquet tensors |
| `output_dir` | `outputs/R1_M1_ablation` | Base directory for run-specific outputs |
| `notebook_path` | `None` | Uses the supplied embedded core when no original source notebook is resolved; inspect provenance recorded by the runner |
| `groups_csv` | `None` | Optional verified mapping with columns `filename,group` |
| `group_level` | `filename_group` | Does not assert subject separation |
| `preflight_only` | `False` | Set `True` to audit real data and front ends without feature-model fitting |
| `mode` | `study` | `smoke` uses synthetic inputs and reduced budgets |
| `resume` | `True` | Reuses compatible checkpoints after fingerprint checks |

Do not set `notebook_path` to a legacy QT notebook. Those notebooks implement a different model. The embedded source is sufficient for the default ablation workflow.

The runner probes scientific imports in a fresh process. With `RUNTIME['environment']='auto'`, it reuses a healthy environment or creates/reuses a dedicated cached virtual environment. Set `RUNTIME['environment']='isolated'` to select the managed pinned environment, or `'current'` to require the configured interpreter. Set `allow_install=False` to disable installation; a missing or incompatible environment then needs to be prepared manually. Managed recovery supports Python 3.10–3.13 and may require network access or a configured wheelhouse.

## Input contract

Place `.parquet` tensors directly in the configured directory; the loader is not a recursive dataset discovery tool. Hidden metadata and `.pgm` previews are ignored. The source filename suffix determines the binary label: `-walking` is 1 and `-not_walking` is 0. The loader also supports legacy `-standing` and negative spelling aliases; the completed study's negative class is **not walking**, not a redefinition as standing.

The numerical pipeline expects finite two-dimensional tensors with a consistent sensor-row count. Width is selected from each training partition; shorter evaluation tensors are padded and wider tensors are cropped using the fitted width. The runner validates shape, feasibility and fitted transformations. Changing tensors, labels, preprocessing or grouping changes the experiment.

The completed supplied run loaded 680 tensors: 483 negative and 197 positive. Two exact-duplicate sets contain four records, including one pair with conflicting labels. All are retained with their original labels. Original filename groups, exact numeric tensor identities and common-prefix collision constraints are joined into connected components, giving 678 effective groups in this run. These groups cannot cross either outer or inner boundaries.

Filename-derived groups are not verified subject IDs. A genuine `groups_csv` can support a different grouping experiment, but it changes the evaluation and cannot be presented as reproducing the recorded filename-grouped result.

## Recommended execution sequence

1. Supply the original tensors and edit paths. Set `mode='study'` and `preflight_only=True`.
2. Execute the first code cell. Inspect the data-quality PDF, loading/duplicate audits, split audit and contraction diagnostics. A `diagnostic_only` result is not a completed model evaluation.
3. For the recorded protocol, confirm three outer and three inner folds, 680 records, 678 effective groups and the other settings in Supplementary Table S1. The feasibility search can use alternative split seeds or reduce folds, so inspect its actual decisions rather than assuming requested settings were achieved.
4. Reset `preflight_only=False` and execute the cell for the complete study. The runner evaluates all 12 configured arms and records completion only after aggregation and reports have been written.
5. Preserve the run directory, launch receipt and environment information. Compare identifiers and settings before comparing numbers; numerical and environment differences may prevent bit-for-bit reproduction.

For a software-only check, set `mode='smoke'`. It uses synthetic data, one CEM epoch, two mirrored pairs, two run seeds, a smaller compiler dictionary/search and 100 bootstrap replicates. Smoke outputs are marked as synthetic and cannot replace real-data results.
